# Pre-checkpoint Quality Checklist

Run this before presenting the Phase 1 draft.

**Fidelity**
- [ ] Every number from the source appears with its arithmetic chain and intermediate results.
- [ ] Any disagreement between sources (or between a source and reality) is surfaced in a callout, not silently resolved.
- [ ] Sections beyond the books are marked ☆ and the mark is explained in "How to use".
- [ ] Web-searched facts are paraphrased (no quotes over ~15 words) and listed in References.

**Completeness (study guide)**
- [ ] Part 1 has real-world use *and* why-it's-a-good-question.
- [ ] Requirements table includes at least one open question the book doesn't pin (freshness, history depth).
- [ ] API + data model present, with a tiny worked example.
- [ ] Life-of-a-request walkthrough touches every component in the diagram.
- [ ] ≥ 3 diagrams: architecture, write/build path (if distinct), one structural illustration.
- [ ] Deep dives cover: core structure, update/freshness, sharding, deletion, persistence/recovery, caching/client, replication, ranking (where applicable).
- [ ] Trade-off summary table, glossary, references present.
- [ ] 12–14 practice questions with hint ladders; checklist rows paired strong/weak; timeline references question numbers.

**Voice**
- [ ] No sentence addresses the interviewer ("let them…", "probe…") in the study guide.
- [ ] No verbatim probe copied into the practice questions without reframing to the candidate.

**Scenario pack**
- [ ] All 10 sections, probe bank in the fixed `P# / L1 / L2 / Expect` format, timeline references probe numbers.

**Build (Phase 2)**
- [ ] Viewed every rendered diagram PNG.
- [ ] Viewed the contact sheet: no near-empty pages, no diagram alone on a page, tables not split mid-row.
- [ ] Shared PDF + markdown together.
